# الباب الخامس — تصنيف الأدلة واليقين

## 12. التصنيف الإلزامي

كل نتيجة يجب أن تحمل تصنيفًا واضحًا:

**CONFIRMED**

حقيقة مدعومة بدليل مباشر من المصدر الذي يثبتها، مع ذكر المرجع والـCommit أو الجدول أو سجل التشغيل أو وقت الفحص متى توافر.

**UNKNOWN**

معلومة لا توجد أدلة كافية لتحديدها.

**CONFLICT**

وجود عقدين أو دليلين حاليين موثوقين ومتعارضين. اعرض الطرفين ولا تحسم بالتخمين.

**UNVERIFIED**

ادعاء أو نتيجة متوقعة لم يجر اختبارها مباشرة، بما في ذلك النشر أو Runtime أو E2E غير المنفذ.

يجب التمييز دائمًا بين:

- SOURCE CODE.
- PRODUCTION DATABASE.
- DEPLOYMENT ARTIFACT.
- RUNTIME BEHAVIOR.
- BUSINESS-DATA EFFECTS.

لا ترفع UNKNOWN أو UNVERIFIED إلى CONFIRMED اعتمادًا على تقرير قديم أو استنتاج غير مباشر.

### ب. المخزون

لا يتغير المخزون إلا بعد إثبات واقعة الاستلام أو التسليم أو الصرف الفعلية بمستند معتمد ومسار مركزي وسجل تدقيق.

لا تعدّل الأرصدة مباشرة لتجاوز مشكلة واجهة.

### ج. الخزينة والصندوق والعهد

لا تتغير الأرصدة لمجرد إنشاء طلب دفع أو سند غير منفذ أو فاتورة.

يجب إثبات تسليم أو قبض النقدية فعليًا بالمستند المعتمد.

### د. حسابات الموردين والعملاء

لا يُرحّل رصيد لمجرد إنشاء مسودة أو مستند غير مكتمل.

يجب الفصل بين حالة المستند وحالة الاستلام وحالة السداد أو التحصيل.

### هـ. المسارات المركزية

لا تنشئ كتابات جانبية أو منطق أعمال مكررًا بين التطبيقات.

استخدم الإجراءات المركزية المعتمدة بعد التحقق من توقيعاتها وسلوكها وصلاحياتها الحالية.

### و. الممنوعات

- تعديل الأرصدة أو السجلات المحاسبية مباشرة.
- إنشاء حركات أو قيود وهمية.
- استخدام بيانات Production الحقيقية كبيانات اختبار.
