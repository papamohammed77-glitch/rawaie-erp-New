#### core.js

Therefore it is not the root cause of the current failure.

#### Actual root cause
The voucher source contains an invalid JavaScript object literal.

The first parser failure is:

```
this.newWorkspace();
}
actionFor:function(v)
```

The missing delimiter is the comma after the `choose` method.

Because the entire `App` object fails to parse, execution does not reach the DOMContentLoaded initialization path:

```
App.init()
```

Therefore the visible symptom "cannot pass the login screen" is a parser failure before application initialization, not an authentication failure.

# 15. Competitive Gaps — Not Emergency Patches

The following should be considered only as future Business Contract closures after owner approval/evidence:

### Transfer-in-transit visibility

Business Central and SAP explicitly model stock in transit in multi-step transfers.

RAWAEA currently models:

```
Sent
→
Received
```

but does not yet expose a dedicated monetary/quantity "in-transit stock" read model as a first-class dashboard object.

This is a legitimate future enhancement, not a defect in the current transfer lifecycle.

### Before / After stock visibility

Daftra exposes Available Before / Available After during transfer.

RAWAEA already calculates source available stock in the voucher workspace, but a formal before/after transaction snapshot could strengthen review and audit UX.

### Detailed movement explorer

Daftra provides transaction-level filtering by:

- date;
- type;
- product;
- warehouse;
- source/reference;
- inward/outward;
- notes.

RAWAEA already has `inventory_log` and audit/report infrastructure. A richer voucher-centric movement explorer is a future read-model enhancement, not a new stock engine.

### Batch / bulk operations

Odoo and Business Central expose batch-oriented warehouse operations.

RAWAEA can later add bulk voucher processing only if the business contract requires it.

### Barcode / physical counting

Odoo explicitly supports assigned inventory counts with barcode scanning.

RAWAEA already contains scanner support and stock adjustment infrastructure. The next enhancement should therefore connect the existing scanner capability to controlled count assignments rather than building another counting engine.

### Attachments / source documents

Daftra exposes attachment support around stock requests/transfers.

A document attachment relationship may improve operational evidence and auditability later.

### Warehouse sublocations / bins

Business Central and Odoo support deeper warehouse location structures and bin-directed workflows.

RAWAEA currently operates primarily at branch/vehicle stock level.

This should not be invented inside the voucher screen until the warehouse-location contract is established globally.
