# 7. الجراحة الثانية — نقل marker النسخة بدل فقدانه

لأن `RW_PWA_RECONSTRUCTION_VERSION` موجود حاليًا داخل الكتلة التي سيتم حذفها، لا نريد إسقاط marker الحوكمة.

## ابحث عن النهاية التالية داخل النسخة authoritative

```javascript
window.RW_Items = RW_Items;
// MAIN2_GOVERNED_CLOSED:v1
```

## أضف فوق هذا السطر مباشرة

```javascript
window.RW_PWA_RECONSTRUCTION_VERSION='MAIN2-COMPLETE-SURGICAL-v1';
```

فتصبح النهاية:

```javascript
window.RW_Items = RW_Items;
window.RW_PWA_RECONSTRUCTION_VERSION='MAIN2-COMPLETE-SURGICAL-v1';
// MAIN2_GOVERNED_CLOSED:v1
```

هذا يحافظ على marker نفسه ولكن تحت المالك الحقيقي للوحدة.

الدليل المباشر أن النسخة Compatibility هي التي تحمل marker حاليًا، بينما النسخة authoritative تنتهي بعد `window.RW_Items = RW_Items` وقبل Main3. fileciteturn1314file0L2-L2

# 8. الجراحة الثالثة — إزالة Global aliases القديمة لـ Main1

داخل كتلة Main1 القديمة توجد العبارة التالية في سطر assignment طويل:

```javascript
window.RW_Dashboard={render:renderDashboard};
window.RW_Items={render:renderItems};
```

## احذف هذين الجزأين فقط

لا تحذف السطر الطويل كاملًا، ولا تحذف بقية globals مثل `RW_POS` و`RW_Orders` و`RW_Runsheets` وغيرها.

### لماذا

النسخة authoritative Main2 تعيد تعريف:

```javascript
window.RW_Dashboard = RW_Dashboard;
window.RW_Items = RW_Items;
```

والـMain3 navigation يبني routes مباشرة من:

```javascript
window.RW_Dashboard
window.RW_Items
```

وبالتالي aliases Main1 القديمة لا تضيف capability، لكنها تترك ownership ثانيًا للاسم نفسه. الدليل المباشر على الـroute table يوضح أن Main3 يعتمد على globals الحالية. fileciteturn1314file0L2-L2

# 9. ما لا نحذفه الآن

## لا تحذف `actions`

يوجد:

```javascript
var actions={dashboard:renderDashboard, ... items:renderItems, ...}
```

ولا ينبغي حذف هذا الكائن في نفس الجراحة؛ السبب أن هذا يمثل **Legacy Main1 navigation closure** مستقلة عن حذف Compatibility Main2، وما زال يلزم فصل Consumer tracing الخاص بها قبل حذفها نهائيًا.

الأدلة المباشرة تثبت أن Main3 يعيد `nav.navigate` إلى route table الجديدة، لكن ذلك لا يساوي وحده إثبات أن كل consumer خارجي لـ`actions` أصبح صفراً. لذلك لا نعالج هذا كجزء من جراحة Main2 الحالية. fileciteturn1314file0L2-L2

## لا تحذف `main1Delegation`

هذه الوظيفة تمثل compatibility boundary لبقية التطبيقات المتخصصة:

```text
pos
teleSales
purchases
receiving
vouchers
picking
loading
delivery
returns
unloading
```

وهي ليست جزءًا من Main2 capability، لذلك حذفها هنا سيكون توسعًا غير مثبت.

# 15. Final CTO Judgment

هذه الجولة لا تحتاج “استرجاع ملف main2”.

الـOriginal أثبت أن القدرات موجودة أصلًا، والـCurrent أثبت أن القدرات موجودة في النسخة authoritative؛ المشكلة هي أن نسخة Compatibility مكررة فوقها، مع false-capability stubs وlegacy aliases.

لذلك الجراحة المطلوبة هي:

```text
DELETE duplicate MAIN2 COMPATIBILITY block
        ↓
MOVE MAIN2 version marker to authoritative module
        ↓
REMOVE only old Main1 Dashboard/Items global aliases
        ↓
KEEP Main1 delegation/action closure untouched for its separate consumer-cleanup unit
        ↓
NO new Main2 functions
NO whole-file replacement
NO rewrite of Dashboard
NO rewrite of Items
```

هذه هي أقل جراحة مثبتة بالمصدر ولا تنقل الدين إلى نسخة ثالثة.
