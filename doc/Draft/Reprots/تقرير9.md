## 6. التحقيق في Production Runtime

سجلات Supabase API أثبتت وجود 401 متكررة من Chrome 151 عند:

```text

```

ومنها:

```text

2026-09-01T20:55:18.968Z
```

لكن سجلات Supabase لا تعيد قيمة `apikey` التي وصل بها الطلب، وبالتالي لا يجوز الادعاء بأنها قيمة بعينها.

وفي المقابل أثبتت سجلات Supabase Auth أن نفس runtime hostname:

```text
https://erp-frontend.mh0537413487.workers.dev
```

```text

2026-09-01T16:16:45Z
```

### النتيجة

Supabase Auth نفسه كان يعمل من نفس runtime hostname ثم ظهرت حالة 401 لاحقًا.

هذا يحول المشكلة من "مشكلة ثابتة في Supabase" إلى مشكلة في الحد الفاصل بين:

## 8. التحقيق في Service Worker — Defect تاريخي مثبت

النسخة التاريخية كانت تستخدم:

```javascript
navigator.serviceWorker.register('../sw.js',{scope:'../'})
```

ومن ثم كان المتصفح يطلب:

```text
/companies/sw.js
```

بينما الـworker canonical موجود تحت:

```text
/companies/company-1/sw.js
```

P144 أصلح registration نفسه إلى:

```javascript
navigator.serviceWorker.register('./sw.js',{scope:'./'})
```

ولأن runtime قد يكون ما زال يخدم artifact أقدم، تم في P146 أيضًا إضافة compatibility rewrite للمسار التاريخي.
