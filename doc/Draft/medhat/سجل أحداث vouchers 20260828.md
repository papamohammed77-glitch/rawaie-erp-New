### Actual gaps found and fixed
#### 1. DirectReturn physical lifecycle mismatch
The UI contract required Vehicle → Branch with SEND followed by RECEIVE, while the prior deployed RPC path did not implement the SEND leg correctly for `DirectReturn`.

Fixed in Production migration:
`vouchers_direct_return_two_stage_authorization_20260828`

Result:
- DirectReturn SEND now posts `InventoryDecrease` through `post_stock_movement` against the vehicle VAN stock branch.
- DirectReturn RECEIVE posts `DirectReturn` through `post_stock_movement` into the target branch.
- COMPLETE remains a state-only close.
- No separate Physical Stock engine was introduced.

#### 2. Server-side voucher authorization
The SEND and manual-post capabilities now validate an active actor in the requested company and require authorized warehouse/voucher roles (or wildcard owner semantics) server-side. UI checks are not treated as the security boundary.

#### 3. Audit actor loss through SECURITY DEFINER
For voucher state mutations executed by service-role Edge Functions, the existing audit trigger previously logged `system` because JWT claims were not present inside the SECURITY DEFINER call.

Fixed in Production migration:
`vouchers_audit_actor_wrapper_layer_20260828`

The existing Production function bodies were retained and renamed as immutable core implementations; same-signature wrappers now set a transaction-local `app.user_email` context before invoking the original function. `fn_audit_trigger()` reads JWT actor first, then this explicit application actor context, then falls back to `system` only when neither exists.
